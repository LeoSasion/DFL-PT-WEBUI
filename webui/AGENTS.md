# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Product Decisions

- The user approved implementing the complete 2026-09-08 interaction audit. Preserve the existing workstation shell and algorithms; improve workflow clarity and recovery rather than introduce a new visual direction.
- Safe stops are normal outcomes, distinct from failed/lost tasks and from available model artifacts. Retain genuine training previews and persisted loss history after stopping; keep history independent of the selected terminal tab and expose resume with saved model settings.
- Label iteration targets as progress estimates when they do not stop training. Offer existing models and detected devices as choices, group/search tasks, and keep low-level execution details in expandable sections.
- Make person review a first-class cleaning step reachable from SRC, DST, and workspace. Require a named, reviewed selection before assignment; preserve source media on cross-side assignment, archive replaced target media and affected outputs, and expose recovery. Mark review status stale when the dataset fingerprint changes.
- Put playable results first on export and workspace pages. Explain normal versus mask outputs, expose copy-path/open-folder actions, and persist generation parameters independently of job logs. Historical records must not imply historical video files are retained when current files may have been overwritten.
- Treat XSeg as optional in readiness indicators. Keep primary actions reachable at compact widths, avoid multiple nested scrolling regions in person review, and support dialog focus trapping, Escape, and visible keyboard focus.
- Training controls follow the live ME job before a selected historical terminal. A missing explicitly named checkpoint must require model selection, never silently substitute another saved model. Loading model metadata is distinct from a missing model; forced stops and save timeouts must not claim a verified safe save.
- Person-review selections, labels, thresholds, and destinations survive in-app navigation in a bounded, project-and-side-scoped memory draft. Browser reload clears that draft; the server must revalidate the dataset fingerprint before any assignment. Recovery retries return a durable completed receipt without repeating file moves.
- Task creation distinguishes new-model intent from resuming a saved model, rejects duplicate names using Windows case rules, and shows actual command-specific output paths. Keep failed preflight and failed submission in the dialog with an actionable retry.
- A failed workspace or recovery-history read is an unknown state, never an empty inventory. Preserve the last successful read with a visible error and retry. Video replacement, restoration, and task-log archiving use an in-app confirmation showing the target and scope; uncertain write responses require checking the result before another write. Authoritative job lists remove archived jobs without discarding jobs created during an in-flight refresh.
- Project switching waits for the target ID and available workspace from live service health before entering. Bound activation and readiness waits, treat lost responses as uncertain, and let users continue checking without repeating the switch write. Show the running project separately from a requested selection; retain failed project-list reads with retry. Preview the normalized project directory using shared frontend/backend identity rules, reject duplicates and Windows reserved names, and never replace an unreadable project registry with a default list.
- Background operation cards retain the last known progress through connection loss, label uncertain state, suppress stale ETA estimates, and offer a read-only progress check. Cancel requests have bounded waits and verify lost responses with a read before allowing explicit retry. Notify terminal outcomes only for work observed during the current session; missing records are unknown, never successful. Person analysis can retrieve the original operation result after polling fails, and normal cancellation is not an error. Keep the local context loader inline without covering its toolbar or duplicating the global operation card.

- On 2026-10-18 the user authorized eight more hours of TAE training following the recommendation to reduce the base learning rate to 5e-5, keeping BS8, grad_clip1, LCT, expanded feather and random_warp=false. Base learning-rate changes on stopped resume preserve weights/iteration/data, reset AdamW/warmup and record the rate in stage history. Migrate existing sampler/reference fingerprints instead of resetting them.

- On 2026-10-17 the user requested disabling random warp on the active TAE model while retaining LCT/expanded-feather and the original ten-hour absolute cutoff. Expose random_warp as resume-mutable with a recorded stage; migrate legacy sampler/reference fingerprints without resetting data state. A fixed cutoff includes resumed preparation and must never restart the original duration.

- On 2026-10-16 the user requested resuming the existing TAE pretraining model with LCT replacing RCT and the accepted expanded-feather mask enabled, for a 10-hour training limit. TAE color transfer exposes none/RCT/LCT, reuses native transforms on SRC input and target, and keeps sampler state through a recorded optimization-stage change.

- On 2026-10-16 the user requested TAE-only training-mask modes: native face / expanded feather / full aligned crop. Expanded coverage adds 10% of resolution (512: radius 51 px). The user refined feathering to span the whole added radius: weight 1 at the native 0.5 contour, linearly falling to 0 at the outer edge, without a full-weight plateau outside the face. Keep face-mask-head targets and eyes/mouth regions native. Treat changes on stopped resume as a recorded new optimization stage. Background-image blur is a separate concept; do not merge ME's existing blur_out_mask control into this setting. Do not start training for this change.

- On 2026-10-14 the user added 512 to the TAE resolution presets for RTM2 pretraining (Inter 384, hidden 96, batch 4, frozen Encoder/Decoder), and requested launching through WebUI to exercise the real workflow. Expose explicit common-pool pretraining in the TAE task wizard, restore the checkpoint mode and pool on resume, and keep ordinary SRC/DST training separate.
