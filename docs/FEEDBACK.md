# 用户实测反馈

通过 [GitHub Issues](https://github.com/LeoSasion/DFL-PT-WEBUI/issues/new/choose) 反馈安装失败、运行错误或功能建议。选择“安装或运行问题”可按字段填写；已有相同问题时补充环境与重现信息即可。

在 WebUI 顶部点击“版本与反馈”，或在启动器失败页点击“准备反馈信息”。选择失败步骤后，程序在本机整理应用版本、启动器版本、安装来源、固定源码提交/内容摘要和诊断计数。先预览，再复制到 Issue 的版本、环境及日志字段，并补充最小重现步骤、预期与实际行为。“打开 Issue 页面”只打开官方模板，不传送预览内容，也不会自动提交。

两处入口使用 `release/feedback.mjs` 与同一模板；Node 尚不可用时启动器提供不含原始日志的离线摘要。诊断读取失败时环境字段标记未知。流程不读取图像 API 配置，不收集原始终端输出、素材名、项目名、私有绝对路径、模型文件或 API Key，不自动上传附件。已有诊断导出仍可单独保存到本机，提交前请自行复核内容。

最有用的信息：

- 版本或源码提交、安装方式（源码/便携包）、Windows 版本。
- 显卡与驱动、运行设备、Python/Node 版本；无法取得时写“未知”。
- 最小重现步骤、预期行为与实际行为。
- 相关任务日志的错误段、发生时间；训练问题可附模型配置、保存/停止时的迭代和错误，不必上传检查点。
- 包恢复失败时附分卷名称、下载大小、校验错误。使用恢复脚本或 `SHA256SUMS` 可核对下载是否完整。

日志或截图中出现私人路径、视频、人脸材料或凭据时，先移除这些信息；优先使用可以公开的最小示例。代码仓库和发行包不会包含本地工作材料。正式画质和双卡报告欢迎后续用户提供，本阶段不要求这些结果才能提交反馈。
