# 四项改进验证（2026-10-05）

应用源码版本为 `0.1.2-preview`，启动器版本为 `0.1.3-preview`。本轮覆盖固定来源与主动升级、首次使用向导、图像结果复核与另存、共享反馈入口。保留黑绿工作站界面与既有可恢复的数据流程。

## 功能与证据

- 固定来源：启动器从内嵌公开提交及官方 codeload ZIP SHA-256 安装，校验应用版本及 ZIP 根目录。安装记录和源码内容清单分别记录实际来源与文件完整性，不读取本机私有 Git HEAD。源码归档和启动器 provenance 分开记录公开提交。
- 主动升级：空闲检查覆盖项目的 Node/Python/FFmpeg 进程及 WebUI、传统终端。先保留源码、界面构建与 Node 依赖，失败自动回退；恢复前完整检查事务路径和所有备份摘要，损坏备份不会先移动当前构建。工作区、模型、配置、凭据与运行时保留。Git 工作副本拒绝 ZIP 覆盖。
- 首次使用：空工作区引导导入 SRC/DST，可创建受管项目；仅有 SRC 时提示 DST，两侧材料导入后定位环境检查。服务在线、入口/工具资源存在、GPU 检测及实际训练预检分别处理。材料导入不创建训练任务。
- 图像复核：同一原图的跨任务结果版本可选，原图和结果同步缩放、键盘平移；参数、实扣费用或未结算状态跟随版本。另存核对原始结果 SHA-256，以实际图片格式创建独立副本；重复名称也不会覆盖原图或既有副本。生成图缺少 DFL 标注时提示重新提脸和检查标注。
- 反馈：启动器与 WebUI 共用 PT 模板，预览、复制后由用户自行打开官方 Issue。摘要只重建允许的版本、来源摘要、环境布尔值、计数和任务状态；不收集媒体、模型、Key、日志全文或私有绝对路径。诊断失败保留未知状态，不编造就绪信息。

## 发行和边界

`release/source-pin.json` 保存应用有效载荷的公开提交、代码树和官方 ZIP 摘要；`release/source-files.json` 保存稳定源码内容摘要。先公开有效载荷提交 P，再用其官方 ZIP 固定来源到发布提交 Q：启动器从 P 安装，启动器构建来自 Q；来源元数据和安装记录不纳入源码内容摘要，避免自引用。源码发行归档的安装记录对应该归档实际公开提交 Q。

本地新资产分别位于 `release-output/launcher-v0.1.3-preview` 和 `release-output/v0.1.2-preview-source`，每类有独立 SHA-256 与 provenance/manifest。根目录 `DFL-PT-WEBUI.exe` 同步为新构建。GitHub 源码同步与本地资产生成不代表 EXE 资产已上传发行页。历史 `v0.1.1-preview` 便携资产未重打，保留原版本、文件与摘要。

图像浏览器验证使用离线人工图片和模拟结算记录，不调用付费平台或读取真实 Key。启动器浏览器验证使用模拟桥；未宣称干净 Windows 机器上完整在线安装/升级已实测。没有变更 ME 桥或追加训练、双卡、视觉质量验收；现有短跑验收与历史未验证事项保持原记录。源码包继续携带已验证的官方通用 XSeg 推理权重、固定摘要和来源许可。
