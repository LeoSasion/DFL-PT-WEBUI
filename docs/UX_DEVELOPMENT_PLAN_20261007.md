# 使用流程与 UX 开发计划

日期：2026-10-07。状态：已按用户意见实施，并完成本轮隔离功能验收及文档/回归同步。实际浏览器 200% 缩放未验证，相关限制单列；独立发行验收随 v7 外部报告记录（该文档不自证包 SHA）。逐项证据见 [本轮验收记录](UX_ITERATION_ACCEPTANCE_20261007.md)。

依据：本次产品流程审计，以及用户的修正：“除了第一点，其他都同意 纳入开发计划。第一点如果有歧义可以优化 修正，不要只变‘下一步’”。本计划规定后续开发范围；原审计的建议和历史截图不代表功能已完成。

## 1. 第一项的修订边界

原审计中涉及主流程调整、导航收敛和筛选入口的建议，按以下边界修订：

- 保留完整流程概览、各阶段入口、当前状态和自由跳转能力。用户可以回到上游复核，也可以使用已有有效产物继续工作。
- “下一步”是依据当前项目给出的建议动作，不取代完整流程，也不成为唯一入口。
- 优先修正阶段命名、状态含义、入口去向、前置条件和用户已选择的数据之间的歧义。不能只更换按钮文案而保留相互矛盾的判断。
- 人物确认、质量复核、训练集选择、训练配置分别说明用途和输入输出；入口之间可互相引导。原“直接合并清洗入口”建议不作为既定实现要求。
- Best Training Faceset 保持可明确选择的训练集方案，不强制每个项目重新筛选；已有 aligned、已确认选集和已有模型的使用路径继续可用。
- 修正用户明确选定的 SRC/DST 输入在切页或重开向导后丢失，属于选择状态的一致性修复；不因此自动改用 selected、覆盖检查点配置或启动任务。

以下各项均需遵守本节，特别是项目导航、任务向导和下一步推荐。验收时同时检查“建议是否正确”和“用户是否仍能自主进入其他阶段”。

## 3. 各项实现与验收要求

### UX-01：统一状态，保留完整流程

本轮实施与验收：统一文件发现与推荐依据，区分历史检查点和本次保存确认，已有成片/合成优先。状态场景回归通过；真实 GUI 逐项等待并确认九阶段内容可见，原页面与自由跳转保留。未执行新成片导出，已有产物状态分支由行为回归覆盖。

分别表达项目阶段、有效产物、最近任务状态和保存确认。例：“历史检查点可用，保存于某时；最近任务已结束，但本次保存未确认”，并提供检查恢复点的动作。没有校验依据时不能写“已验证”。

已有模型或成果不等同于本次任务成功；旧任务失败也不直接否定此前有效成果。素材变化时显示需要复核或更新的相关产物。顶部流程、总览、任务卡和全局状态使用一致判断，保留必要的上下文差异。

数据审计同时显示“可用”与“发现问题”时，明确可训练、建议关注、必须排除各自的含义和数量关系，避免把软提示误读为硬拒绝。

验收场景包括：仅有 aligned、训练中、保存中、停止后保存未确认、已有有效检查点、已有合成、已有成片、上游素材变化。完整流程和手动跳转仍可使用；不因缺少两份诊断快照而无理由推荐重新训练。

### UX-02：明确采用哪一套 SRC 和 DST

本轮实施与验收：两侧选择独立保存、版本冲突与有效性检查已接入。真实 GUI 形成 revision 2 的成对引用，切页/侧别、刷新、服务重启、切换新项目后返回均恢复；显式填入才改变本次输入，64 px 检查点配置不自动改。QA 源文件变化时 SRC 引用失效、填入禁用，DST 保持有效；精确恢复字节后两侧有效。

训练配置显示两侧输入卡：人物/用途、来源类型、可用数量、选集日期与版本、有效性。默认路径与用户明确选择区分处理；不存在历史选择时沿用既有默认和检查点配置规则。

项目保存用户的选择，任务创建时生成本次输入快照。分别设置 SRC 与 DST 时不丢失另一侧；多个窗口修改时发现版本冲突并提示。重新打开已有模型时，项目偏好不能悄悄覆盖检查点中已保存的训练配置，差异走现有续训确认和采样重置机制。

验收：切页、关闭弹窗、重启服务、切换项目再返回；撤回、篡改、缺失、跨项目或未完成发布的选集不能被误用；对原始 aligned、目录、PAK/ZIP 等既有输入仍执行原有检查。用户仍可主动切换输入。

### UX-03：草稿与恢复

本轮实施与验收：草稿按项目/侧保存，冲突暂停，来源失效时旧确认不可用。真实切页、侧别、刷新、服务重启与项目切换恢复通过；QA 图片临时附加一字节时 API 返回 source/identity false，界面阻止采用，随后恢复原 SHA。恢复草稿不自动启动任务。

按项目和 SRC/DST 保存未提交参照、最近计划、分类和页码；字段合法时保存数量偏好。身份确认必须绑定原素材与参照版本，来源变化时不能照搬旧确认。已保存计划、未提交草稿和已发布选集分别标识。

页面回到上次位置并提供“继续上次选集/新建选集”。恢复草稿不自动启动分析或重新发布，也不把已取消的操作当作继续运行。

验收包括本次审计复现路径：勾选参照 → 切到源帧修复 → 返回，选择保留；切 SRC/DST、项目与服务重启后不串用数据；原素材发生变化时正确失效。

### UX-04：人工复核与版本

本轮实施与验收：新版本支持保留/排除/暂缓、批量、撤销及分类数量，保留原建议与回执，CAS/重试保护回归通过。真实 GUI 的 SRC 母计划 6/6/2 经人工复核成为子版本 6/5/3，并完成预演和发布；真实 CLI 另验证撤回与原件/旧回执不变。

提供“保留、排除、暂缓”与逐张/批量操作、未完成数量和撤销。文件名、简短理由、算法分类、人工决定同时可追溯。“同人参照”是身份定义，与保留决定独立。

人工修订产生新的选集版本，保留原推荐及原发布回执。新版本继续经过身份、成员、原素材哈希与发布校验；不得通过普通人工“保留”绕过无法读取、无有效 DFL 元数据等训练输入硬约束。review 中质量达标的备选与真正待人工判断项应清楚区分，不把全部备选强制变成待办。

已发布选集保持可验证，修订不就地改写旧回执或删除原媒体。保留决策持久化、并发版本检查、取消恢复、发布前预演以及撤回能力。

验收：复核中断再继续、误操作撤销、批量裁决、参照变更、素材变更、重复提交、旧版本仍可查看与恢复；新版本只在明确确认后用于训练。

### UX-05：后台结果可返回

本轮实施与验收：终端上方独立结果栏显示最新结果，最近三项主动展开并支持 Esc 还焦。真实结果点击定位到正确 DST 选集及 1/2/0 计数；独立 GUI 确认结果栏不遮挡编辑动作，原项目切换保护保留。

沿用现有跨页面进度、取消与重连机制。完成/失败卡显示项目、侧别、操作对象和结果摘要，动作定位到对应选集或具体修复入口。历史记录采用时间、输入数量、保留数量和状态，而不是主要依靠短 ID。

验收：离开页面后完成，通知直接回到正确结果；当前项目不同则先走已有项目切换保护；失败可从正确阶段恢复，避免重复执行已成功的发布。

### UX-06：筛选首屏

本轮实施与验收：首屏突出参照、数量上限和分析生成，详细控制与高级评分折叠，500 分批和 60 分页分别说明。真实两侧分析、浏览和发布闭环通过；组件行为、草稿保存及三个桌面视口检查已有证据。

优先展示人物参照、数量上限、当前数据和开始动作。模型名、评分依据、研究对照保留在高级信息；生产评分继续采用当前已确定的方案，不因 UX 改造扩展 FIQA 候选。

可将建立计划、全量分批分析和生成建议串成一个开始动作，但阶段、分析范围、取消和中断恢复始终可见。逐批操作保留在可访问的详细控制中，输出副本仍需用户审阅并明确确认。数量始终是上限。

验收：1280 × 720 下主要任务可发现；每批最多 500 张及选定范围可见；每页浏览与全量分析数量不混淆；缺资源、未确认身份、分析未完成时解释准确。

### UX-07：项目入口

本轮实施与验收：项目标题菜单已接入新建和切换，目录及运行保护保留。真实新项目切换后返回恢复原草稿/输入；独立 GUI 验证菜单焦点圈定、Esc 和 opener 还焦，项目隔离及运行保护另有行为回归。

项目标题提供当前项目、最近项目及新建入口。创建表单保留目录预览及受管路径约束，名称与标识帮助清楚；是否切换到新建项目由用户明确选择。原设置入口可保留为管理入口。

说明“项目”与“工作区素材管理”的区别；工具入口按用途解释，保留原有功能的直接访问能力。

运行中的任务、恢复操作或未保存编辑继续受现有保护。验收项目切换前后的素材、模型、草稿、选集与后台结果均属于正确项目。

### UX-08：具体动作与续训

本轮实施与验收：具体动作直达参数、全局新任务选择和续训摘要已接入。真实已有 64 px 模型未被项目偏好自动修改，小样直达参数且可选择 short-run；向导跨刷新保持原任务。独立菜单/CTA/焦点检查及参数行为回归通过，原预检和配置保护保留。

全局“新建任务”保留任务选择；从明确的提取、合成、导出等按钮进入，直接显示对应参数并提供“更换任务”。保留预检、执行摘要、明确启动和失败后配置恢复。

续训首屏展示模型和保存信息、已保存配置摘要、设备、数据集和运行计划。需要更改时展开原配置及差异；网络结构保护、允许配置变更、优化器/采样状态重置规则继续生效。摘要可展开查看全部参数，不能通过简化把高级能力删掉。

验收不同入口的初始步骤、重新打开不残留上次预检、无效字段定位、关闭/还焦、键盘操作和参数一致性。

### UX-09：遮罩与合成用途

本轮实施与验收：遮罩简洁栏与用途展开、中文合成说明、1–20 帧独立小样已接入。真实 GUI 两帧 CPU 小样成功、三联图 2/2 与下一张通过，相同参数的正式预检通过后取消；未执行全片。真实原生小样及 11 项生命周期检查通过；独立 XSeg 未保存 Cancel/Accept 保护通过且 JPG SHA 不变。

遮罩入口清楚区分“应用内置/已训练遮罩”“手工修正”“训练辅助 XSeg”，展示已有标注和应用状态，按需求引导。保留直接编辑入口。

合成模式与遮罩模式提供中文用途说明。小样预览使用明确的帧范围、独立输出和当前参数，并显示它不是全片结果；适用时复用现有预览/复核能力。复核 DST 遮罩的源帧绑定、缺失拒绝和身份/几何约束继续生效。

验收自动应用与手工编辑的状态区分、未保存编辑保护，以及预览和最终参数一致性；不引入新模型。

### UX-10：诊断与交付

本轮实施与验收：诊断可选、已有模型可经预检合成，导出显示数量、补齐动作与已有成片。真实诊断/导出页面内容可达，前置条件与已有产物/失败状态回归通过。本轮未执行真实新成片导出，不能据页面和单元测试声明交付视频质量通过。

诊断不足两个快照时解释比较所需条件，提供与当前运行状态匹配的动作；没有可评测进程时不能显示一个永远不可执行的唯一入口。已有有效模型仍可经检查进入合成，诊断不成为无依据的强制训练门槛。

导出页读取合成产物就绪度。无 merged 时提供去合成；有产物时展示数量、音轨与输出位置等必要信息，再配置母版/播放版。已存在成片优先呈现查看、生成记录和按需重导出。

验收无产物、部分产物、已有完整成片、上游已变更和上次导出失败等状态，避免仅修改提示却允许使用无效输入。

### UX-11：图像与键盘

本轮实施与验收：遮罩更多菜单、宽度记忆、短屏滚动、连续复核/快捷键及含文件名的控件名称已接入。1280×720、1440×1000、1100×800 无 document 横向溢出；独立短屏菜单、宽度与焦点、V10 空终端 CTA 滚动可达通过。640×360 仅作 200% 内容容量模拟，真实浏览器 200% 缩放未验证。三个真实 DOM 文本样本对比度为 16.30:1、8.86:1、11.07:1，仅证明所测样本，不声明整界面标准合规。原验收要求不删改。

改善 SRC/DST/XSeg 右侧工具拥挤和文字截短，高频动作可见，其余收进可发现的更多菜单；支持可用范围内调整面板宽度，并记住用户布局。终端可收起，任务异常和等待回答保持可发现。

放大复核支持上一张/下一张、左右键与当前位置；接受/排除等快捷键只在对应上下文中生效，输入框内不误触发。参照复选框的可访问名称包含文件名。增大关键标签和说明的可读性，保留焦点圈定、Esc 和关闭还焦。

验收 1280 × 720、1440 × 1000、1100 × 800 及 200% 缩放、键盘连续复核、焦点与可访问名称。涉及颜色调整时测量关键文本对比度，不能只从截图宣称符合标准。

### UX-12：文档与发布

本轮实施与验收：README、中文指南、Best 指南和验收记录已同步；完整 Node V5 为 409 passed / 2 skipped / 0 failed，Python 73 passed。独立 R1–R10 均修复并复检；FINAL2 构建和 dist-provenance 校验通过，最后加载提示纯文案由构建/浏览器验证。来源冻结和独立发行验收随 v7 外部报告记录（该文档不自证包 SHA）；旧 v6 包与历史失败保持原样。

同步用户流程、入口名称、状态含义、恢复说明及当前模型选择，清理已失效的旧名称；特别核对 README 与最佳训练人脸使用说明。开发计划中的项目只能在实际完成对应验收后改为完成。

实现后的源码、前端构建、来源清单和后续发行包统一更新。已有 v6 包及其验收记录继续代表旧快照，不改写为包含本计划；保留原失败及历史证据。

| A：一致性与恢复 | UX-01、UX-02、UX-03、UX-05 | 统一状态依据，保留明确的两侧选择和草稿，结果可以正确找回 |
| B：人工复核 | UX-04，加 UX-11 的连续复核部分 | 完成可撤销、可追溯、可恢复的人工修订版本 |
| C：界面与流程减负 | UX-06、UX-07、UX-08、UX-09、UX-10、其余 UX-11 | 完整流程仍可见，各入口解释清楚，具体任务减少重复步骤 |
| D：集成与交付 | UX-12 | 真实界面、隔离素材、恢复闭环和发行验证 |

数据与状态契约先于表层改名。UX-02 与 UX-04 共用选集版本及有效性校验；UX-03 与 UX-05 共用定位信息；UX-01 为各处推荐动作提供一致依据。可独立的项目入口、向导交互和布局任务可并行开发，避免多个任务同时改同一状态契约。

## 5. 验证及兼容底线

- 以当前真实页面和组件为视觉基线，不做未经选定的整体重设计；完整工作流和高级参数继续可访问。
- 原 aligned、DFL 元数据、关键点辅助文件、媒体与检查点不因 UX 迁移被重写或删除。现有发布、回执、恢复、隔离记录继续可读。
- 单次分析最多 500 张、配对比较每批最多 250 张的限制及选定范围继续可见；全量选集和当前浏览页的范围分别显示。
- 新增草稿、偏好、人工决定采用明确版本、项目范围与原子保存；旧项目缺少这些记录时保持可用。来源失效、冲突或旧确认不可用时明确显示状态，不悄悄切换输入。
- 为选择持久化、人工复核版本、来源变化、状态分支和事务恢复编写必要的行为测试；纯文案/布局修改使用构建与界面验证，不堆砌复刻实现的测试。
- 在隔离项目实际验证创建/切换、草稿恢复、两侧输入、人工复核、新版发布、训练配置预填、撤回与原图 SHA 保留。不要用单元测试替代上述界面闭环。
- 本轮不以训练质量证明作为 UX 验收。若实现触及 ME 桥接，按 AGENTS.md 和 ME_SHORT_RUN_ACCEPTANCE.md 执行总计一小时内的隔离小模型训练、保存、停止、恢复与预测；不做长训或双 GPU 验收。
- 后续每批记录实际通过、失败、跳过及未验证范围；“已纳入计划”不等同“已经开发完成”。
