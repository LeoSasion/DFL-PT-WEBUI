# 非训练流程整改：H3CE 基线与质量对照方案

日期：2026-10-06。根据用户“应用最佳方案，更新我们的各个环节”的后续指示，已进入生产接入阶段；**模型选择只看质量，不以速度、显存、吞吐量决定优先级。** 第一轮候选对照保留在 [历史报告](NON_TRAINING_UPGRADE_RESULTS_20261006.md)，当前实现与验收状态见 [质量方案应用记录](QUALITY_PIPELINE_APPLIED_20261006.md)。

## 1. 选择原则

每类先复现 H3CE 的具体模型、权重与输入协议，再尝试两个独立候选。H3CE 没有的身份模型与语义遮罩，以 DFL 现有 SFace 和已校验的通用 XSeg 为兼容基线；不把 H3CE 的眼嘴关键点轮廓当作分割模型。

比较用相同源素材、固定输出尺度、正确的各自预处理，并在运行前锁定协议。速度与显存只记录运行环境和失败原因，不进入质量分数或名次。所有候选均运行，不沿用旧方案“唯一首轮候选”“先出现三次失败就淘汰”的缩减规则。

| 类别 | 基线 | 两个候选 | 质量判断及限制 |
|---|---|---|---|
| 检测 | H3CE YOLO11m-face | YOLO12l-face、YOLO26s-face | 框真值不足时不报 AP/Recall；固定 TUFA98 的下游轮廓误差只能说明检测与关键点组合表现 |
| 关键点 | H3CE TUFA98 | ORFormer98、Regression98 | 共享检测框，原生点集；另测 TUFA68、FAN68 兼容路径；不将 98 点截成 68 点，也不伪造 3D |
| 修复 | H3CE SwinIR-L x4 PSNR | Real-ESRGAN_x4plus、GFPGANv1.4 | 统一 512 输出，新增退化恢复与清晰输入保持分别评分；感知距离不能替代身份保真 |
| 人物特征 | DFL SFace | AdaFace IR100/WebFace12M、MagFace iResNet100 | 同一 112 五点对齐；未确认人物标签时不报 TAR/FAR 或质量赢家 |
| 遮罩 | DFL generic XSeg WF | BiSeNet/CelebAMask-HQ、SAM2.1 Hiera large 提示分割 | 先声明面部、头发、遮挡、背景的目标语义；不同语义不能直接对同一张输出排名；人工真值不足时 IoU/Dice 留空 |
| 感知度量 | H3CE LPIPS-Alex v0.1 | LPIPS-VGG v0.1、DISTS | 同一尺寸/像素域；未取得人工偏好时只记录距离，不声称某个度量与人类更一致 |

精确模型 ID 和检测器资产锁见 [候选清单](../tools/vision-model-candidates.json)。候选规模由官方可复核的权重确定，不能用模型名称或参数规模推断质量优越性。

评分必须区分确定性功能验证、探索性样本得分、可信质量验收。样本小、参考由非专家绘制、身份未确认或缺少人工遮罩时明确标记，不编造准确率。候选差异不足以证明收益时继续保留现有默认。模型迁移与模型质量升级分别验收。

用户进一步指定模型标注准确性的视觉评分由 **GPT-6 Astra low** 执行。后续沿用匿名候选、原图与可见区域核对、评分锁定后揭名的流程，逐例保留理由和不可判定项；视觉指数不冒充专家真值或准确率。首轮已完成 60 份关键点、36 份检测、18 份遮罩输出复核，见 [Astra 盲评记录](VISION_ASTRA_VISUAL_REVIEW_20261006.md)。

## 2. 借鉴 H3CE 的范围

借鉴固定资产、严格加载、源图坐标与仿射记录、内容绑定缓存、真实 PTS、保守几何关联和失败经验；在本项目独立实现。H3CE 自有源码记录为 AGPL-3.0-only，不整目录复制，也不建立运行时绝对路径或虚拟环境依赖。上游官方网络源码、权重及原许可单独留档。

H3CE 的关键点难例、固定的非专家参考轮廓可用于本轮探索性重测；只读核对原图 SHA，不修改源图或参考。原图已有缺陷时，它只能是“原始输入相对参考”，不能重新称为 pristine HQ。

历史 SwinIR、Restormer、NAF 没有跨条件普遍胜出的失败记录继续保留。串联增强、重复缩放、输入域不匹配可能导致回退；LPIPS 改善不证明细节真实、身份保持或视频稳定。H3 Encoder/Dense/Decoder 训练修复链不并入此次非训练整改。

参考定位：H3CE 的 `components.lock.json`、`docs/VIDEO_PREPARATION.md`、`docs/DETECTOR_HOST_PROTOCOL_20260911.md`、`docs/H3_LANDMARK_PRECISION_RESULTS_20260914.md`、`h3ce/data/face_geometry_tracks.py`、`h3ce/data/stable_head.py`、`h3ce/cache/keys.py`、`docs/archive/LESSONS.md`。这些是参考项目相对位置，不是本项目导入路径。

## 3. 已开始实施的契约

### 3.1 模型与缓存

- 下载与推理解耦，推理不联网自动安装、下载或替换权重。每份资产记录具体模型、来源、上游提交、字节数、完整 SHA-256、代码与权重条款及输入输出语义。
- 统一 PyTorch 推理；历史 SFace ONNX 只解析原权重，由 PyTorch 执行。ONNX 导出验收依赖保留，不能因运行时统一误删。
- 完整加载权重并核对形状、有限值；不能用随机初始化或本地 QA 训练权重填补缺失的官方资产。
- 结果记录原图框/点、原生点定义、原图与模型坐标变换、模型身份、配置和失败原因。缓存绑定源内容、模型、适配器与预处理/数值设置；失败、取消、损坏缓存不当作成功结果。
- 候选权重、私有图像、对照结果保存在 ignored `workspace/.vision-models` 或 `workspace/.vision-evaluation`。候选不会因本机已跑通而自动加入公共发行包。
- 源码包与便携包继续携带原有已验证 generic XSeg、散列与来源/许可记录。

### 3.2 提取与几何

WebUI 新提取默认 YOLO26s-face，关键点方案默认 TUFA，JPEG 质量默认 100；依据为固定难例的有限对照、Astra 视觉复核和随后真实生产提取检查，不宣称通用检测赢家。S3FD/manual 与其他 YOLO 模型仍可显式选择；CLI 的旧 FAN 默认保持兼容。缺资产立即说明，不静默回退；检测对照使用同一 img960、FP32、置信度与 NMS 约定。YOLO26 官方 face 权重实际带 pose head，检测框可用于提取，但其点输出不写入旧 68 点字段。

普通二维提取已接入原生 TUFA68，仍使用现有 DFL 68 点对齐协议；同一网络的原生 TUFA98 独立写入审核命名空间与哈希绑定侧车，不截取成 68 点，也不自动生成训练遮罩。HEAD 保留真实 FAN3D 权重及其 68 XY 输出，另外保存 TUFA98 审核；不伪造深度。人工调整保留既有几何流程。ORFormer98/Regression98 继续作为评测候选。已有 aligned 与 ME 训练/合成几何协议不自动改写，实测和限制见 [关键点生产协议](VISION_LANDMARK_PRODUCTION.md)。

下一步时间稳定应采用双向唯一关联；切镜、缺口、歧义、多人交叉处断轨，轨迹只说明几何连续性。最多前后两帧、基于实际 PTS 的中心和尺度平滑必须保留原值、使用值及回退原因；不得统一平滑眼睛开闭、嘴形和表情。阈值需要 DFL 短片重新标定，本轮不将 H3CE 常数直接设为产品默认。

### 3.3 相似图与人物

描述子召回后以同尺度 SSIM 逐对复核，组内每对都过门槛，取消链式传递合并。代表图按清晰度、曝光、源人脸尺寸和可靠仿射一致性选取；缺失分项不参与，侧脸与闭眼不自动判废，也不捏造遮挡分数。分项显示供人工复核。

SFace 迁移通过原 OpenCV 推理逐项数值对照后才接入。人物聚类继续 complete-linkage、同帧互斥和人工复核；AdaFace/MagFace 在身份真值与阈值校准完成前不沿用 SFace 阈值或切换默认。

保留原生工作台、每轮最多 500 张、两批比较每批最多 250 张、批次范围、可恢复隔离与保存副本。

### 3.4 媒体与输出

复用项目内 FFmpeg/ffprobe。抽帧清单记录原整数 PTS、time_base、源帧号、源内容身份、色彩和音轨信息。选帧记录真实映射，不以 `r_frame_rate` 虚构 VFR 时间。清单与图像一起归档/恢复。

通用 H.264/yuv420p 播放版保留；CRF0 限定为编码后的 YUV 样本保持，不称 RGB 全链路无损。新增 FFV1 bgr0/NUT RGB8 母版，回读逐帧像素、时间和音轨，保存 `.media.json`。母版不能恢复源视频已有损失或认证源色准。NUT 浏览器不支持直接播放，提供下载及本地查看。

音轨可以原包复制时验证原包；有非零起点或 priming 等情况显式转换 PCM 并验证解码样本，不能虚称仍为 AAC 原包。输出微秒时间精度与原整数时间分别记录。HDR/高位深等未支持输入明确拒绝，不静默降成普通 SDR。

“导出母版与播放版”已组合 RGB 母版和 MP4 播放版，输出成片/遮罩各两种格式，共四个视频及四份 `.media.json` 校验记录；不能把母版替代通用播放版。

源帧修复保持可选，推荐 SwinIR-L PSNR；只在新输出上使用一个模型，不串联增强。输出为同尺寸 RGB8 PNG 副本，再经 YOLO26s/TUFA 提取至独立 `aligned_restored/<taskId>`。`source_map` 将 PNG 映射回原帧名并记录来源与输出哈希，恢复输入保留奇数宽度原画布，已实测 259×194 不裁边。原帧、原 aligned 与原元数据保留，修复 PNG 不复制旧 DFL 元数据。

BiSeNet 已接入面部辅助遮罩草稿、原图/遮罩/边界复核与完整 aligned 副本发布。眼、嘴、耳等前景类别保留；预测不伪造人工 polygons。用户复核后才保存独立完整副本，未选择的图也独立复制；generic XSeg 权重、人工标注和原 aligned 保留。训练 SRC/DST 人脸集与合成 DST 人脸集可显式选择经过审核、位于当前 workspace 内的副本，禁止外部或逃逸链接路径。SAM2 仍为评测候选，短片传播、人工修正及切镜闭环需后续证据。

## 4. 验证和发布门槛

每类固定最多 24 图与限定短片，逐候选运行并保留全部成功/失败。功能验证检查颜色通道、坐标往返、旧 DFL 元数据、缓存失效、恢复与媒体往返。性能不进入评分。当前探索性协议不冒充标准数据集或正式质量验收。

默认提升要求可靠标注或审核、预设主要质量项有可复核收益、关键领域无严重回退，并明确对应适用范围。公平采样、模型专属输入预处理与阈值校准不可省略。质量不成立时保留旧默认，已验证的基础整改仍可交付。

本轮不启动训练，不更改 ME 桥接或架构。未来若触及桥接，严格遵守 [一小时内短训验收](ME_SHORT_RUN_ACCEPTANCE.md)，不恢复旧长训、最终视觉质量或真实双 GPU 门槛。

正式发行另检查新运行时依赖、资产条款、源码/便携包一致性和回退；本机候选测试不等于已经发布。未实现的时间稳定、颜色/遮罩时序和辅助标注闭环保持明确待办，不写成完成能力。
